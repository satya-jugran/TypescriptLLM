Chapter 1 Fundamentals

The Core Mental Model: From Text to Vectors

What is an LLM, what is a Transformer, and how does text convert into continuous geometric vectors?

💡 Concept Primer: Definitions & Mental Models

What is an LLM? A Large Language Model is a statistical neural network trained on vast text datasets to predict the single most likely next token given an existing sequence of context words.

What is a Transformer? Introduced by Vaswani et al. in 2017 ("Attention Is All You Need"), the Transformer is a deep learning architecture that processes sequence relationships in parallel using Self-Attention rather than sequential recurrence (like RNNs or LSTMs).

How does text generation work? Text generation is autoregressive: the model outputs one token, appends that new token to the prompt context, and feeds the entire expanded context back through the network to generate the next token, repeating until an End-of-Sequence (<|endoftext|>) token is reached.

What is Tokenization? Computers cannot process raw text strings like "Paris" directly. Tokenization cuts text into chunks called tokens (characters, subwords, or words) and maps each to an integer ID from a fixed vocabulary (size 65 in miniGPT, 49,152 in SmolLM-135M).

What is an Embedding? A token ID is merely an arbitrary index (19556). It carries no semantic geometry: token 19557 is not "close" to 19556. An Embedding maps each discrete token ID into a continuous vector space (RD) where geometric distance represents semantic similarity.

How Language is Tokenized & Embedded

Before any neural computation happens, text is tokenized into integer IDs and mapped to continuous vector rows in an embedding table:

Example Prompt:
"The capital of France is"
"The" → ID: 19556
" capital" → ID: 905
" of" → ID: 17
" France" → ID: 15169
" is" → ID: 3511

Contiguous Table Slice Implementation

Embedding lookup is NOT an expensive matrix multiplication. It is a direct row slice from the embedding table: row i starts at offset i × hiddenSize:

projects/smollm-inference/model/transformer.ts Zero-Matmul Embedding Lookup 
// Slicing floats directly from the contiguous embedding table
const hiddenSize = 576;
const embedData = new Float32Array(seqLen * hiddenSize);
const tableData = this.embedTokens.data;

for (let i = 0; i < seqLen; i++) {
  const tokenId = inputIds[i];
  const tableOffset = tokenId * hiddenSize;
  const targetOffset = i * hiddenSize;
  
  // Fast memory copy of contiguous floats
  embedData.set(
    tableData.subarray(tableOffset, tableOffset + hiddenSize),
    targetOffset
  );
}
Chapter 2 Fundamentals

The Tensor Abstraction & Flat Memory Layout

Memory layout, contiguous buffers, strides, and cache-friendly CPU math.

💡 Concept Primer: What is a Tensor?

Definition: A Tensor is a generalized multi-dimensional array of numerical values. A 0D tensor is a scalar (7), a 1D tensor is a vector ([1, 2]), a 2D tensor is a matrix (rows & cols), and 3D/4D tensors represent sequence lengths, attention heads, and features.

Why can't we use standard JavaScript number[][]? In JavaScript, number[][] is an array of object references pointing to other arrays scattered randomly across the V8 heap. This causes massive CPU cache misses and triggers frequent garbage collection pauses. TypescriptLLM stores all data inside flat, contiguous Float32Array memory.

What are Shape and Stride? Shape defines the dimensions (e.g. [2, 3]). Stride indicates how many memory elements to skip to advance by 1 unit along that dimension. In row-major layout: stride[k] = ∏i > k shape[i].

The GEMV Optimization Trick (Y = X WT)

Hugging Face linear layer weights are saved in shape [N, K] where N = out_features and K = in_features. When decoding a single token, X is a vector of length K. Computing Y = X WT means each row n of W performs a dot product with X:

Y[n] = ∑k=0K-1 X[k] × W[n, k]

Because both X and row n of W are linear contiguous memory slices, the CPU streams bytes with stride 1, enabling auto-vectorization and zero matrix transpositions!

src/core/tensor.ts 8-Way Loop Unrolled GEMV 
// Contiguous inner dot product with 8-way unrolling
for (let n = 0; n < N; n++) {
  const wRowOffset = n * K;
  let sum = 0.0;
  let k = 0;
  const unrollLimit = K - 7;
  for (; k < unrollLimit; k += 8) {
    sum += xData[k]     * wData[wRowOffset + k]
         + xData[k + 1] * wData[wRowOffset + k + 1]
         + xData[k + 2] * wData[wRowOffset + k + 2]
         + xData[k + 3] * wData[wRowOffset + k + 3]
         + xData[k + 4] * wData[wRowOffset + k + 4]
         + xData[k + 5] * wData[wRowOffset + k + 5]
         + xData[k + 6] * wData[wRowOffset + k + 6]
         + xData[k + 7] * wData[wRowOffset + k + 7];
  }
  for (; k < K; k++) {
    sum += xData[k] * wData[wRowOffset + k];
  }
  outData[n] = sum;
}
Chapter 3 Fundamentals

Self-Attention & Causal Masking

Scaled Dot-Product Attention (Q, K, V) and why triangular masking enforces the arrow of time.

💡 Concept Primer: Scaled Dot-Product Attention

What is Attention? In traditional architectures, tokens were processed in isolation or via sequential recurrence. Attention allows every token in a sequence to look across all other tokens simultaneously and dynamically compute how much information to borrow from each.

The Query, Key, Value Metaphor: Attention acts like an information retrieval database:
• Query (Q): What the current token is searching for (e.g., "I am the verb 'is', who is my subject?").
• Key (K): What each candidate token offers or advertises (e.g., "I am the noun 'capital'").
• Value (V): The actual semantic content payload communicated if Query and Key match.

The Attention Formula: Attention(Q, K, V) = Softmax((Q · Kᵀ) / √d) · V

Why Scale by 1/√d? When the head dimension d is large (e.g. 64), dot products can grow very large in magnitude. Large values push the Softmax function into flat saturation regions with near-zero gradients. Scaling by 1 / √d preserves variance = 1 and maintains stable numerical gradients.

Why Causal Triangular Masking? In autoregressive language modeling, a model must predict token t based only on past tokens 0 … t−1. To enforce this "arrow of time", a lower-triangular causal mask sets all future attention positions (where col > row) to −Infinity. After Softmax, e^(−∞) = 0, guaranteeing zero probability of leaking future tokens.

The Causal Attention Mask Matrix

During parallel sequence evaluation, tokens form a square attention score matrix. The upper triangle is masked with −∞ so that future tokens receive zero attention weight:

Attending Token (Query) pos 0 ("The") pos 1 ("capital") pos 2 ("of") pos 3 ("France")
Row 0: "The" 1.00 (Self) −∞ (Masked) −∞ (Masked) −∞ (Masked)
Row 1: "capital" Score(1, 0) Score(1, 1) −∞ (Masked) −∞ (Masked)
Row 2: "of" Score(2, 0) Score(2, 1) Score(2, 2) −∞ (Masked)
Row 3: "France" Score(3, 0) Score(3, 1) Score(3, 2) Score(3, 3)

Pure TypeScript Implementation

Both miniGPT (projects/mini-gpt/nn/Attention.ts) and SmolLM (projects/smollm-inference/layers/attention.ts) implement this exact scaled dot product with triangular masking:

projects/mini-gpt/nn/Attention.ts Scaled Dot-Product with Causal Mask 
// 1. Raw dot-product scores scaled by 1 / sqrt(headDim)
const scale = 1.0 / Math.sqrt(headDim);
const scores = q.matmul(k.transposeLast2()).mul(scale); // [B, numHeads, T, T]

// 2. Apply triangular causal mask (future positions -> -Infinity)
for (let r = 0; r < T; r++) {
  for (let c = r + 1; c < T; c++) {
    scores.data[r * T + c] = -Infinity;
  }
}

// 3. Row-wise Softmax ensures probabilities sum to 1.0 per query row
const probs = scores.softmaxRows();

// 4. Weighted combination of Value vectors
const context = probs.matmul(v); // [B, numHeads, T, headDim]
Chapter 4 Fundamentals

Sampling & Generation Dynamics

Turning raw logits into probabilities, Temperature, Top-K, Top-P, and Repetition Penalty.

💡 Concept Primer: Logits & Samplers

What are Logits? The raw, unnormalized scores output by the final LM-Head projection for every token in the vocabulary (49,152 numbers).

What is Greedy Sampling? Selecting the token with the highest score (argmax). Fast and deterministic, but prone to getting stuck in repetitive loops.

What is Temperature? Dividing logits by temperature T: Low T (0.2) makes probabilities peaked and deterministic. High T (1.0) flattens probabilities, producing diverse and creative outputs.

What is Top-K Sampling? Truncating candidate tokens to only the top K highest-probability choices and discarding everything else.

What is Top-P (Nucleus) Sampling? Selecting the smallest dynamic set of tokens whose cumulative probability mass exceeds P (e.g. 90%).

What is Repetition Penalty? Dividing the logits of previously used tokens by a penalty factor (≥ 1.0) to prevent repetitive loops.

Autograd: Teaching Math to Backprop

How a reverse-mode computation graph records every operation so the chain rule can compute exact analytical gradients — the engine inside projects/mini-gpt/autograd/Tensor.ts.

💡 Concept Primer: Definitions & Mental Models

What is a Gradient? In calculus, the gradient (∂Loss/∂θ) answers one fundamental question: "If I nudge weight θ up by a tiny amount, does the total error go up or down, and by how much?" Neural networks learn by nudging every weight in the opposite direction of its gradient.

What is Automatic Differentiation (Autograd)? Hand-calculating derivatives for millions of parameters is impossible. Numerical differentiation (finite differences: (f(x+h) − f(x−h)) / (2h)) requires running a forward pass for every single parameter — taking hours for one step! Autograd solves this by recording operations into a Directed Acyclic Graph (DAG) during the forward pass, and then applying the chain rule in reverse to compute exact derivatives for all parameters simultaneously in a single backward pass.

Why Reverse-Mode and not Forward-Mode? Forward-mode autograd propagates derivatives from one input to many outputs. Reverse-mode propagates derivatives from one scalar output (Loss) back to millions of inputs (weights). Because neural network training always maps millions of weights to a single scalar loss, reverse-mode is millions of times faster.

Why Topological Sort? A node's gradient cannot be passed backward until all nodes that depend on it have already contributed their gradients. Topological sorting ensures we visit nodes in strictly reverse execution order.

Why Gradient Accumulation (+=)? The multivariate chain rule states that if a parameter affects the loss through multiple pathways (e.g. shared embeddings or residual connections), its total gradient is the sum of the gradients from each path: ∂L/∂x = ∑ (∂L/∂y_i · ∂y_i/∂x). Therefore, gradients must always accumulate (grad += ...).

Why call zeroGrad()? Because gradients accumulate with +=, if you don't reset .grad to zero before each step, gradients from step 1 leak into step 2, compounding indefinitely and causing the model to diverge.

How miniGPT Implements the Engine in TypeScript

Inside projects/mini-gpt/autograd/Tensor.ts, each Tensor stores its data, grad, and an array of _parents edges. Each parent edge stores a gradFn closure that executes the specific derivative rule for that operation:

projects/mini-gpt/autograd/Tensor.ts Forward Graph Construction with gradFn Closures 
// Every operation records its derivative rule as a closure
mul(other: Tensor): Tensor {
  const out = new Float64Array(numel(outShape));
  for (let i = 0; i < out.length; i++)
    out[i] = a[i % a.length] * b[i % b.length];

  const outT = new Tensor(out, outShape, this._requiresGrad || other._requiresGrad);

  if (this._requiresGrad) {
    // Chain rule: ∂L/∂a = ∂L/∂out · b
    outT._parents.push({
      tensor: this,
      gradFn: (g) => {
        for (let i = 0; i < g.size; i++)
          this.grad[i % a.length] += g.grad[i] * b[i % b.length];
      }
    });
  }

  if (other._requiresGrad) {
    // Chain rule: ∂L/∂b = ∂L/∂out · a
    outT._parents.push({
      tensor: other,
      gradFn: (g) => {
        for (let i = 0; i < g.size; i++)
          other.grad[i % b.length] += g.grad[i] * a[i % a.length];
      }
    });
  }
  return outT;
}

Topological Backward Traversal

Calling loss.backward() initializes loss.grad = [1.0] and runs a depth-first search (DFS) to build a topological ordering of the DAG. It then iterates backwards through the sorted list, calling each node's gradFn:

projects/mini-gpt/autograd/Tensor.ts Topological Backward Pass 
backward(): void {
  this.grad[0] = 1; // Seed: ∂Loss/∂Loss = 1.0

  // 1. Build topological sort (depth-first search)
  const topo: Tensor[] = [];
  const visited = new Set<Tensor>();
  const visit = (t: Tensor) => {
    if (visited.has(t)) return;
    visited.add(t);
    for (const p of t._parents) visit(p.tensor);
    topo.push(t);
  };
  visit(this);

  // 2. Iterate in reverse topological order
  for (let i = topo.length - 1; i >= 0; i--) {
    const t = topo[i];
    for (const { gradFn } of t._parents) {
      gradFn(t); // propagate gradients into parent .grad buffers
    }
    t._parents.length = 0; // free graph edges to reclaim memory
  }
}
Chapter 2 miniGPT

The Training Loop & Optimization

Batch Sampling → Forward Pass → Cross-Entropy Loss → Backward Pass → AdamW Step — the five-step heartbeat that turns random weights into a language model.

💡 Concept Primer: Definitions & Mental Models

What is the Training Loop? The fundamental iterative cycle in machine learning. In each step: (1) sample a batch of text windows, (2) predict the next characters via forward pass, (3) quantify error using cross-entropy loss, (4) backpropagate gradients via autograd, (5) update weights with AdamW, and (6) reset gradient buffers to zero.

What is Cross-Entropy Loss? For next-token prediction, cross-entropy measures how surprised the model is by the actual correct token: Loss = −log(P(correct token)). If the model assigns 100% probability to the correct token, Loss is 0. If it assigns 0% probability, Loss is infinity.

Why is Shakespeare Initial Loss Always ≈ 4.17? With randomly initialized weights, a model assigns uniform probability across all vocabulary symbols. For a 65-character vocabulary, P(correct) = 1/65 ≈ 0.01538. The expected initial loss is −ln(1/65) = ln(65) ≈ 4.174. If training starts at ~4.17 and drops, the model is learning; if it starts at 10.0 or 0.1, weight initialization is broken!

What is Perplexity (PPL)? Perplexity is e^Loss. It represents the effective branching factor: the number of equally probable choices the model is guessing between. At step 0, PPL = e^4.174 = 65 (completely clueless across all 65 characters). At step 100 with Loss = 2.1, PPL = e^2.1 ≈ 8.1 (down to just 8 plausible candidate characters!).

Why AdamW? AdamW (Adam with Decoupled Weight Decay) maintains two statistics per parameter: (1) Momentum (m) dampens high-frequency gradient noise, and (2) RMS scaling (v) adaptively normalizes step sizes across parameters. Finally, Decoupled Weight Decay applies regular weight decay directly to θ (rather than dividing it by variance), providing stable convergence across all Transformer layers.

The Four-Step Implementation

projects/mini-gpt/train/Trainer.ts Core Training Loop Step 
trainStep(): number {
  // 1. Get random batch from Shakespeare corpus
  // Inputs: [B, T] characters; Targets: [B, T] characters shifted by 1
  const { inputs, targets } = this.getBatch();

  // 2. Forward pass: builds autograd graph
  const logits = this.model.forward(inputs, this.config.batchSize, this.config.blockSize);
  const flatLogits = logits.reshape([B * T, vocabSize]);
  const loss = this.lossFn.forward(flatLogits, targets);

  // 3. Clear old gradients and backpropagate
  this.optimizer.zeroGrad();
  loss.backward(); // walks graph in reverse topological order

  // 4. Update parameters using AdamW
  this.optimizer.step();

  return loss.item(); // detach scalar loss
}

Chapter 3 miniGPT

miniGPT — Live Training & Interactive Generation

Watch the loss fall in real time on Shakespeare, then interactively sample character-by-character with temperature controls.

💡 Concept Primer: What is miniGPT?

What is miniGPT? miniGPT is a complete generative Pre-trained Transformer written from scratch in pure TypeScript without any external framework or matrix library. It implements the classic GPT-2 architecture: token + learned position embeddings, pre-LayerNorm transformer blocks, causal multi-head self-attention with triangular masking, GELU feed-forward networks, and a linear language model head.

Why Train on Characters? Commercial models use subword BPE tokenizers with 32,000–128,000 tokens. While compact, high-dimensional vocabularies require massive projection matrices. By restricting vocabulary to 65 characters, the entire training pipeline fits comfortably in CPU memory and trains in seconds.

What Does Temperature Do? During generation, logits z are scaled by Temperature T: P_i = exp(z_i / T) / ∑ exp(z_j / T). When T < 0.5, probabilities peak sharply around the top character (greedy, repetitive). When T = 0.7–0.8, the distribution balances coherence and diversity. When T > 1.2, probabilities flatten, producing wild, erratic, or ungrammatical text.

Class & Object Architecture Call Graph

Complete object hierarchy, ownership composition, and method invocation call graph across training and generation.

💡 Concept Primer: Object Architecture of miniGPT

How is miniGPT structured? The project employs Composition over Inheritance. Every layer is an instance of an abstract Module base class, which registers parameters and delegates forward calls. The top-level Trainer orchestrates data slicing, model execution, loss evaluation, autograd backpropagation, and AdamW weight updates.

How do method calls flow during training? When trainStep() executes, calls cascade down the tree: Trainer → GPT → TransformerBlock → MultiHeadAttention & FeedForward → Linear → Tensor. In reverse, loss.backward() traverses the recorded DAG in reverse topological order, calling each operation's gradFn closure.

The Two Inference Phases: Prefill vs. Decode

Why production LLM inference is strictly divided into compute-bound prompt evaluation (GEMM) and memory bandwidth-bound token generation (GEMV).

💡 Concept Primer: The Physics of Inference

Why are there two distinct phases? An LLM does not execute the same computational workload throughout generation. Evaluating an initial prompt is Compute-Bound: hundreds of tokens are processed simultaneously in parallel matrix multiplications (GEMM). Generating new tokens is Memory Bandwidth-Bound: only 1 token is processed per step, requiring the CPU to stream millions of parameter bytes from RAM for each matrix-vector product (GEMV).

Why project only the last token in prefill? If a prompt has 10 tokens, intermediate layers must compute hidden states for all 10 tokens so they can populate the KV cache. However, to pick token #11, we only need the logits of token #10! Projecting only the final token hidden state (M = 1) to the 49,152 vocabulary logits saves over 80% matrix-vector multiply operations during prefill!

The Two Phases of Inference

Modern LLM inference is strictly divided into two distinct computational phases:

1. Prefill Phase

Compute-Bound

Takes the user's initial prompt (e.g. 10 words) and processes all tokens in parallel. Computes Key and Value projections, populates the KV-Cache, and computes logits only for the final token to sample token #11.

Input: [Batch=1, SeqLen=S, Dim=576]
Operations: Matrix × Matrix (GEMM)

2. Decode Phase

Memory Bandwidth-Bound

Generates tokens one-by-one. In each step, exactly 1 token (S = 1) is projected through the 30 layers, attending to previously cached tokens. 99% of execution time is spent here doing Matrix-Vector products.

Input: [Batch=1, SeqLen=1, Dim=576]
Operations: Matrix × Vector (GEMV)

projects/smollm-inference/engine/inference-engine.ts Orchestrator Facade 
// High-level orchestration in TypescriptLLM
export class InferenceEngine {
  public async generate(request: GenerationRequest): Promise<GenerationResult> {
    // 1. Reset KV-Cache
    this.kvCache.reset();

    // 2. Tokenize prompt
    const promptTokens = await this.tokenizer.encode(request.prompt);

    // 3. Phase 1: Prefill prompt tokens
    const prefillLogits = this.model.forward(promptTokens, 0, this.kvCache, false);
    let currentToken = sampler.sample(prefillLogits, promptTokens);

    // 4. Phase 2: Autoregressive single-token decode loop
    while (generatedTokens.length < maxTokens) {
      if (currentToken === this.tokenizer.eosTokenId) break;
      onToken(await this.tokenizer.decode([currentToken]));

      const stepLogits = this.model.forward([currentToken], currentPos, this.kvCache);
      currentToken = sampler.sample(stepLogits, contextTokens);
      currentPos++;
    }
  }
}

Memory Acceleration: What is the KV Cache?

Eliminating quadratic O(N2) recomputations with pre-allocated state buffers.

💡 Concept Primer: What is the KV Cache?

Definition: The Key-Value (KV) cache is an internal memory buffer that stores previously computed Key and Value vectors across all layers of the Transformer.

Why is it necessary? Without a cache, generating token #100 requires re-running attention for all 99 prior tokens, causing an O(N2) quadratic explosion in computation time. With a KV cache, previous Keys and Values are saved, meaning generating token #100 only requires running the model on token #99!

How is it implemented in TypescriptLLM? KVCacheManager pre-allocates flat Float32Array buffers for all 30 layers up to sequence length 2048. Appending new tokens is a single contiguous copy with zero memory reallocations!

// Append incoming Key/Value projections into pre-allocated memory
public append(layerIdx: number, keys: Tensor, values: Tensor): number {
  const layer = this.layers[layerIdx];
  const incomingTokens = keys.size / this.kvDim;
  const startOffset = layer.currentSeqLen * this.kvDim;
  const numElements = incomingTokens * this.kvDim;

  // Single fast typed array copy
  layer.keyCache.data.set(keys.data.subarray(0, numElements), startOffset);
  layer.valueCache.data.set(values.data.subarray(0, numElements), startOffset);

  layer.currentSeqLen += incomingTokens;
  return layer.currentSeqLen;
}
Chapter 3 SmolLM Inference

The Core Engine: Transformer Block

RMSNorm, Rotary Embeddings (RoPE), Grouped-Query Attention (GQA), and SwiGLU MLP.

💡 Concept Primer: Inside the Transformer Block

What is a Transformer Block? It is the foundational computational module repeated 30 times in SmolLM-135M. Each block takes token representations, updates them with attention context from other tokens, expands them through a feed-forward network, and passes them to the next layer.

1. RMSNorm: Normalizes hidden values so activations don't explode or vanish across 30 deep layers. Why omit mean centering? Removing mean subtraction saves CPU cycles with identical accuracy.

2. RoPE (Rotary Position Embeddings): Attention has no inherent sense of order—it sees tokens as an unordered bag of words. RoPE rotates Query and Key vector pairs in the complex plane proportional to token position m, preserving vector magnitude.

3. Grouped-Query Attention (GQA): SmolLM uses 9 Query heads and 3 Key/Value heads. Three Query heads share one KV head, reducing memory bandwidth by 66%!

4. SwiGLU MLP: Gated activation combining silu(x · Wgate) ⊙ (x · Wup), projecting non-linear features up to dimension 1536 and back to 576.

SafeTensors & BF16 On-The-Fly Math

Binary format parsing, header JSON, and zero-math BF16 to Float32 conversion.

💡 Concept Primer: Weights & Binary File Formats

What are Model Weights? The trained numerical parameters (134 million values in SmolLM-135M) representing the learned knowledge of the neural network.

What is SafeTensors and why not Pickle? Traditional PyTorch .bin files use Python pickle, which can execute malicious arbitrary code upon deserialization. SafeTensors is an open, pure binary format: an 8-byte length header, a JSON metadata dictionary, followed by raw contiguous byte buffers.

What is BFloat16 vs Float32? Standard Float32 uses 32 bits (1 sign, 8 exponent, 23 mantissa). BFloat16 uses 16 bits (1 sign, 8 exponent, 7 mantissa). Because the exponent size is identical, converting BF16 to Float32 simply requires shifting bits left by 16: uint16 << 16!

💡 Putting It All Together: The Complete Inference Lifecycle

In modern LLM inference, generation proceeds in two distinct operational phases:

  • Prefill Phase (Prompt Evaluation): All prompt tokens are processed together in parallel. Key and Value vectors for every token across all 30 layers are stored into the KVCacheManager. Logits are computed for the final prompt token to predict the first new token (Compute-bound GEMM).

Past keys and values are retrieved from the KV-cache, avoiding recomputation. Only 1 row is computed per layer using fast 8-way unrolled GEMV (Memory-bandwidth bound).

Class & Object Architecture Call Graph

💡 Concept Primer: Architecture & Design Patterns of SmolLM Inference

What design patterns are used in TypescriptLLM? The engine employs four core software patterns: (1) Facade Pattern via InferenceEngine, abstracting tokenization, prefill, decode loops, and streaming into a clean API; (2) Builder Pattern via ModelBuilder, assembling 30 Transformer layers with decoupled configurations; (3) Factory Pattern via SamplerFactory, isolating temperature and top-p/top-k logic; and (4) Composite Pattern via the abstract Module base class.

How do Prefill and Decode differ structurally? In the Prefill phase, the full sequence of prompt tokens is processed concurrently to populate the KV cache, but only the final token is projected to vocabulary logits. In the Decode phase, exactly one token is processed per step, performing Matrix-Vector (GEMV) operations while attending to past KV slices without recomputing earlier tokens.

Why is the Key-Value Cache decoupled from layers? Rather than storing state within each attention module, KVCacheManager pre-allocates continuous Float32Array buffers for all 30 layers at initialization. This eliminates garbage collection thrashing during real-time autoregressive generation.
